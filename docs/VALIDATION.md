# 0.2.0 修复与验证记录

基线：GitHub `main` 的 `ab8b130`（2026-09-19 检查）。本次修改保留原有 NumPy/CuPy 手写 Transformer，不引入深度学习框架，不包含新预训练权重。

## 已确认并修复的问题

| 原问题 | 后果 | 修复/验证 |
| --- | --- | --- |
| `randint` 上界为 `len(data) - seq_len - 1` | 刚好 `seq_len + 1` 个 token 会报错，最后一个合法窗口永远取不到 | 修正合法起点范围并测试最小长度/末尾起点 |
| mask 重试失败后退回任意窗口 | 全零监督 batch 被当作 loss=0 的有效训练 | 预计算有效窗口；无合格窗口明确报错 |
| 按连接后的 token 流截断训练/验证 | 同条对话跨集合，重复课程样本泄漏 | 完整对话分组切分，相同格式化内容只留在一侧 |
| 切分前用所有样本训练 tokenizer | 验证数据参与建立词表 | 仅使用训练对话构建词表 |
| assistant-only 编码第二次读取 JSONL | 空行报错，空内容/EOS 处理与第一次读取不一致 | 统一读取、格式化、编码，按对话验证助手监督 |
| `-log(p + 1e-12)` 与 `p - one_hot` 不匹配 | 极小概率的 loss 饱和，梯度却不饱和 | 稳定 log-sum-exp；logits `[1000,-1000]` 的错误目标 loss 为 2000 |
| checkpoint 权重赋值允许广播，未核对结构 | 错误形状可静默加载；相同形状的不同 head 数未被发现 | 严格检查元数据、形状、数值和 tokenizer 指纹 |
| 只保存权重，缺优化器/RNG/日程 | 无法真正继续中断训练 | 新版完整训练状态；精确恢复测试 |
| 验证消耗训练使用的全局 RNG，batch loss 等权平均 | 验证频率改变训练轨迹，监督数量不同的 batch 权重不正确 | 独立固定 RNG，按监督 token 数加权 |
| 训练和采样有两份生成函数 | 修复容易不一致，特殊 token 可被生成，未知 prompt 字符丢失 | 统一生成；禁止 PAD/BOS/UNK 输出；保留原 prompt；支持贪心与固定种子 |
| 默认数据生成路径的父目录不存在 | 新克隆直接运行脚本失败 | 创建输出父目录；拒绝输入输出同文件，避免截断输入 |
| README 推荐不存在的 checkpoint，许可证与 LICENSE 冲突 | 新克隆无法按说明复现，使用条件不清楚 | 发布小样例、依赖文件，历史实验单独保留，明确 MIT |

数值实现参考：[NumPy 对数概率文档](https://numpy.org/doc/stable/reference/generated/numpy.logaddexp.html)；优化器保持 [AdamW 原论文](https://arxiv.org/abs/1711.05101) 的解耦权重衰减形式。代码保留项目原先“不衰减 embedding 和一维参数”的策略。

## 本地验证

环境：macOS、Python 3.12.7、NumPy 1.26.4、CPU。

- 全套 `unittest`：26 个 CPU 测试通过；另有 1 个真实 CUDA 对照测试，当前环境无可用 CuPy/CUDA，跳过。
- 两层、双头、338 个参数的模型逐参数中心差分，包含重复 token、共享 embedding 和部分监督；全部梯度通过 `rtol=3e-4, atol=2e-7` 比较。
- 测试覆盖注意力因果性、AdamW 独立参考计算、极端 loss、有限值保护、原子保存失败、tokenizer/结构不匹配、数据边界、字符/子词两条 CLI 路径。
- 连续训练 6 步，对比训练 2 步后保存并恢复到 6 步：`best.npz` 与 `latest.npz` 内的所有数组/元数据均逐项一致。
- 单个微型训练样本的 80 次更新使 loss 降至初始值的 15% 以下。这是学习链路/过拟合检查，不是泛化能力证明。

README CPU 示例实跑：

| 项目 | 结果 |
| --- | ---: |
| 原创样例数 | 24 |
| 训练/验证对话数 | 19 / 5 |
| 训练/验证 token 数 | 605 / 156 |

生成命令可正常运行和结束，但短语仍有明显重复。此结果只证明小数据训练过程可运行、有优化信号，不能证明模型已经能正确回答新问题。训练 loss 各步使用不同 batch，不应当作严格的同集前后对比。

## 限制与后续验证

- 无 NVIDIA GPU，本次没有验证 CuPy 实际运行、GPU 吞吐量或显存占用。仓库提供可在 CUDA 环境运行的对照测试。
- GitHub Actions 配置覆盖 Python 3.11/3.12、NumPy 1.x/2.x；远端结果以 PR 中的检查状态为准。
- 历史 checkpoint 和大数据集未发布，无法验证原 README 的问答案例、历史指标或训练速度。
- 验证 loss 是固定随机窗口的采样估计；文档分组消除了完全相同文本泄漏，不等于语义去重或严格能力基准。
- 真正提升中文回答质量需要合适的数据、足量训练以及独立的评测任务；本次没有把“训练流程通过测试”写成“回答质量已修复”。
